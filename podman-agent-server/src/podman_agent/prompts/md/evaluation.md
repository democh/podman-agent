## 评估维度（按优先级排序）

1. **正确性**：方案是否能产生正确的结果，是否与现有代码/数据兼容
2. **安全性**：是否避免破坏性操作，失败后的回退成本是否可控（可逆优先）
3. **可行性**：所需工具和资源是否可用，执行路径是否清晰可落地
4. **效率**：步骤是否最少、最简洁，是否避免冗余操作和重复工作
5. **Token 经济性**：方案预估消耗的 token 量（多轮 LLM 调用、大量工具结果都会消耗 token），优先选择消耗更少的方案

## 评估原则

- 如果两个方案在正确性和安全性上同等，选更简洁（token 更少）的方案
- 高风险操作（覆盖文件、执行 shell）的扣分应大于多一步安全读取的开销
- 如果某方案明确标注了"可并行执行多个工具"，在效率维度上加分

如果有多个方案同等优秀，选择编号较小的那个。
