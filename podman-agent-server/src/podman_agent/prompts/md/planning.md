## 规划原则

- 每个步骤应聚焦于一个明确的目标，可以独立执行和验证
- 步骤之间可以有依赖关系（前一步的输出是后一步的输入），也可以是独立的探索性步骤
- 总步骤数控制在 2~8 步，避免过度拆解
- 如果任务简单到无需拆解（如单次搜索、一句话回答），不要输出任何 STEP，直接返回空
- 每个步骤用一句话描述，包含：做什么 + 如何验证完成
- 只规划使用上方列出的可用工具能够执行的步骤

## 并行优化

- 将无依赖关系的独立操作放在**同一步骤**中，系统会自动并行执行（ReWOO）
- 有数据依赖的操作必须拆成不同步骤，确保前置步骤完成后再执行后续步骤
- 优先在第一、二步安排信息收集（并行读取/搜索），为后续步骤提供充足上下文

## 步骤复杂度参考

- **简单步骤**（系统轻量处理）：读取文件、搜索内容、列出目录——适合并行编排
- **中等步骤**（标准处理）：代码修改、创建文件——会触发自动验证
- **复杂步骤**（深度处理）：多文件重构、架构设计——会启动候选方案评估

## 输出格式

严格使用以下格式输出步骤列表：

```
STEP 1: <步骤描述>
STEP 2: <步骤描述>
...
```

不要输出其他说明文字。如果任务不需要拆解，不要输出任何 STEP 行。
