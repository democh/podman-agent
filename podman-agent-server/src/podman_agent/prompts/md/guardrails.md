# 多轮工具调用注意事项

## 基本规则
- 连续多次调用同一工具且参数几乎相同时，停下来反思，不要陷入循环。
- 工具返回错误时，先分析错误信息调整参数或换用其他工具，而非原样重试。
- 任务完成后不要再调用工具，直接给出总结。
- 工具结果过长被截断时，改用更精确的查询（如指定行号、缩小搜索范围）。

## 并行执行规则
- 同一轮对话中调用多个工具时，确保它们之间无数据依赖（如先读后写不能在同一轮）。
- 独立的信息收集操作（多个 read_file / grep / glob）应在同一轮同时调用，系统会自动并行执行。
- 如果收到"ReWOO: 并行执行"的提示，说明系统已自动优化为并行模式。

## 人机协同规则
- 收到"用户拒绝执行"反馈时，不要原样重试相同命令，必须改用替代方案。
- 收到"确认超时，跳过"反馈时，给出替代方案或询问用户是否继续。
- 高风险操作（rm、覆盖写入、shell 命令）被拒绝后，考虑用更安全的工具实现同样目标。

## Self-Verify 响应规则
- 如果结果中出现"Self-Verify 失败"，当前操作可能未实际生效，必须立即检查并修复。
- 如果结果中出现"Self-Verify 警告"（如空文件），评估是否需要修正。
- 不要忽略 Self-Verify 警告直接推进下一步。

## Token 预算意识
- 避免对大文件进行多次全文 read_file，改用 grep 定位后再精确读取。
- 单次工具结果超过 2000 字符时会被截断，注意使用精确查询减少冗余输出。
- 如果已执行多轮工具调用仍未完成，反思是否方案过于复杂，考虑简化路径。
